## 0. פסק דין

**כן, יש רגרסיה — אבל לא ב-`api/ocr.js`.**

לוגיקת הקריאה של ה-OCR לא השתנתה מאז 2026-06-22. הרגרסיה היא **בצד הלקוח**, והיא
נולדה מהתנגשות בין שלושה שינויים שנעשו בטווח של שלושה ימים (21–23.06).

**התסמין "זיהה את המחיר הנוכחי בתור מחיר הכניסה" אינו OCR כלל.**
ה-OCR החזיר `entry: null` — כלומר עשה בדיוק את מה שנועד לעשות ("לעולם לא לנחש").
**את המחיר הנוכחי כתב לשדה `entry` אפקט הציטוט החי בצד הלקוח, כ-250ms אחרי
שה-OCR סיים.** המשתמש רואה שדה מלא ומניח שה-OCR מילא אותו.

זהו כשל שקט בצורתו הקלאסית — `CLAUDE.md` §2 — והוא חמור יותר משגיאת קריאה,
משום שהוא **נראה כמו הצלחה**.

## 2. תשובות לשש השאלות — עם קובץ:שורה

### א. מה קורה כשאין כלי Long/Short בתמונה?

**השרת מתנהג נכון.** `api/ocr.js:421-424`:

```js
if (parsed.hasPositionTool !== true) {
  res.status(200).json({ ...nullResult, ticker, confidence: modelConf });
  return;
}
```

`entry`/`stop`/`target` = `null`. **השרת לעולם אינו קורא את המחיר הנוכחי.**

אבל `ticker` **כן** נשמר — וזו נקודת ההצתה. הרצף:

1. `SwingEdge_App.jsx:2460` — `ticker: f.ticker || result.ticker` → הטיקר נכתב לטופס
2. `SwingEdge_App.jsx:2461-2463` — entry/stop/target נשארים ריקים (`result.entry` הוא null)
3. `SwingEdge_App.jsx:1930-1937` — `useEffect` תלוי ב-`analyzerForm.ticker` **נורה בגלל השינוי בטיקר**, debounce 250ms
4. `SwingEdge_App.jsx:1922` — `if (!force && f.entry) return f;` — `entry` ריק → **ממשיך**
5. `SwingEdge_App.jsx:1923` — `return { ...f, entry: String(q.price.toFixed(2)) }` → **המחיר החי נכתב ל-Entry**

**השומר בשורה 1922 מדלג רק כשה-entry כבר מלא. כלומר המילוי-האוטומטי יורה
בדיוק ורק כשה-OCR נכשל.** ההתנהגות אינה תלוית-מזל — היא דטרמיניסטית.

אותו באג בדיוק ב-Log New Trade: `SwingEdge_App.jsx:1891-1895` + אפקט `:1901-1908`.

### ב. מה ה-confidence שחוזר, והאם `validate()` מפיל אותו?

`api/ocr.js:422` מחזיר `confidence: modelConf` — **הביטחון של המודל, כפי שהוא,
בלי הנחתה**. `nullResult.confidence` הוא 0 (`:355`) אבל **נדרס** ע"י ה-spread.

**`validate()` לעולם לא נקרא במסלול הזה** — הוא יושב ב-`:445`, אחרי ה-`return`
של `:422`. שום דבר לא מסנן את המספר הזה.

התוצאה: מודל שקרא נכון "אין כאן כלי פוזיציה" ומדווח על כך בביטחון 85 — מייצר
תשובה עם `confidence: 85` ובלי אף מחיר.

### ג. `nullResult` — באילו תנאים, והאם המקרה של עומרי היה צריך להגיע אליו?

שלושה מסלולים:
- `:407` — JSON לא פריק
- `:422` — אין כלי פוזיציה (עם `ticker` + `modelConf`)
- `:463-474` — `modelConf < 40` **או** `bothLegsFail`

**המקרה של עומרי הגיע ל-`:422`, וזה המסלול הנכון.** השרת עשה את עבודתו.
הכשל מתרחש **אחרי** התשובה, בצד הלקוח. אין תיקון בשרת שהיה מונע אותו.

### ד. `max_tokens: 300` — האם חיתוך JSON אפשרי?

התשובה הנדרשת היא ~10 שדות, כ-150–200 טוקנים. חיתוך אפשרי אך לא סביר.

**וגם אם יקרה — הוא מתדרדר בבטחה.** `extractJson` (`:86-99`): `JSON.parse`
נכשל, אחריו `indexOf("{")` / `lastIndexOf("}")`. ב-JSON קטוע אין `}` סוגר →
`end === -1` → מחזיר `null` → `:405-409` מחזיר `nullResult` עם `confidence: 0`
→ הבאדג' מציג "לא זוהה — ודא ידנית". **התנהגות נכונה. לא הסיבה.**

### ה. האם הלקוח מציג למשתמש מה זוהה לפני שמירה?

**לא. אין מסך אישור — אומת.** `SwingEdge_App.jsx:2458-2464` כותב ישירות לטופס.
המשוב היחיד הוא באדג' ה-confidence, **ובו הבעיה השלישית**.

`SwingEdge_App.jsx:4116-4130` — הבאדג' נגזר **אך ורק מ-`confidence`**, ולעולם
לא נשאל האם שדה כלשהו באמת התמלא:

```js
const high = ok && confidence >= 70;
...
else if (high) { icon = <CheckCircle/>; text = `OCR ✓ ${confidence}%`; }
```

**התוצאה המשולבת שראה עומרי:**

| מה קרה באמת | מה המשתמש ראה |
|---|---|
| אין כלי פוזיציה, entry/stop/target = null | באדג' ירוק **"OCR ✓ 85%"** עם ✓ |
| הציטוט החי כתב את המחיר הנוכחי ל-Entry | שדה Entry **מלא** — נראה כאילו ה-OCR מילא |
| stop/target באמת ריקים | "לא מילא נתונים" |

זו בדיוק העדות, מילה במילה. הבאדג' הירוק הוא מה שהופך את זה מכשל לכשל **שקט**.

### ו. (נוסף) האם `entry` יכול לחזור מ-Vision במקום מחישוב?

כן — `api/ocr.js:436`: `const entry = computed.value !== null ? computed.value : visionEntry;`

כשהמודל מדווח `hasPositionTool: true` אך לא הצליח לקרוא את האחוזים,
`computed.source === "none"` וה-entry נלקח מקריאת Vision — שעלולה להיות
כותרת ה-OHLC או המחיר הנוכחי.

**והמסלול הזה אינו ניתן ל-cross-check מבנית.** `:458-460`:

```js
const bothLegsFail = computed.source === "none" && stopChecked && targetChecked && !stopOk && !targetOk;
```

`stopChecked`/`targetChecked` (`:163-164`) דורשים `stopPercent !== null` —
אבל `source === "none"` נובע *מכך* שהאחוזים חסרים. **שני התנאים סותרים זה את
זה: המקרה היחיד שבו נעשה שימוש ב-entry של Vision הוא בדיוק המקרה שבו השער
לא יכול לירות.** מסלול נוסף שמייצר "מחיר נוכחי כ-entry", עצמאי מהראשון.

למילוי מהציטוט החי; אין שום שומר נוסף בין `:1922` ל-`:1923`.

**מה עדיין דורש אימות חי** (בסשן עם ניב מחובר):
1. ערך ה-`confidence` בפועל כשאין כלי פוזיציה — האם מגיע ל-≥70 ומצייר באדג' ירוק
2. עיתוי מדויק: האם המשתמש רואה הבהוב של שדה ריק לפני המילוי
3. תרחיש "גרף עמוס" — האם המודל מדווח `hasPositionTool: true` שגוי (מפעיל §2ו)
