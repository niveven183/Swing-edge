## §1 — מאיפה `trades.currency` מקבל את ערכו

### א. המסלול המלא — רישום ידני

טופס → סימבול → מחירים → שמירה. **בשום שלב לא נשאלת השאלה "באיזה מטבע נסחר
הנייר".**

```
טופס עסקה (SwingEdge_App.jsx)
  ├─ שדה סימבול      → טקסט חופשי / בורר TradingView
  ├─ שדה entry/stop/target → מספרים חשופים, ללא יחידה
  ├─ ⛔ אין שדה מטבע  — למשתמש אין מה לבחור, וגם לא צריך להיות לו
  └─ handleSubmit (:2443-2472)
       └─ currency: capitalCurrency        ← ‼️ השורש, :2457
```

הקוד בשורות 2443-2457 מתעד בחירה מודעת — אבל בין שתי אפשרויות **שגויות**:

> ```js
> // A hand-typed trade is priced in the CAPITAL's currency by construction —
> // the form has no currency field and posSize/risk are derived from
> // `capital`, which is denominated in `capitalCurrency`. Stamping the
> // DISPLAY currency here would be the split's worst failure mode: a $150
> // entry saved as "₪150" and then converted again on the way out...
> currency: capitalCurrency,
> ```

ההערה דוחה נכון את **מטבע התצוגה**, ובוחרת את **מטבע ההון**. השלישי — מטבע
המסחר של הנייר — לא נשקל. ההנחה "priced in the CAPITAL's currency by
construction" נכונה רק כשההון והנייר במקרה באותו מטבע; היא הייתה נכונה כל עוד
כל המשתמשים היו דולריים.

**נגזר מהעדפת החשבון? כן, ישירות.** לא מהסימבול, ולא hardcoded.

### ב. מה ב-CSV import — סיפור אחר לגמרי

`src/import/normalizeRow.js:114-138` מפעיל **שרשרת סמכות בת 4 רמות**:

| # | מקור | הערה |
|---|------|------|
| 1 | resolver של פרופיל הברוקר | הסמכות הגבוהה — נגזר מהנתון עצמו |
| 2 | תא ממופה בקובץ | מה שהברוקר כתב |
| 3 | `opts.defaultCurrency` | = מטבע ההון — הנפילה לאותה טעות |
| 4 | `"USD"` | ברירת מחדל אחרונה |

תא שלא ניתן לפרסור **נדחה** כ-`bad_currency` ולא מנוחש. הייבוא גם מחזיק
`divisor` נפרד למחיר: `const price = (v) => (v == null ? null : v / divisor);`.

⚠️ **המסקנה החשובה:** מסלול הייבוא כבר יודע שמטבע הוא תכונה של הנתון, לא של
המשתמש. מסלול הרישום הידני — לא. שני המסלולים כותבים לאותה טבלה.

### ג. למה 59 השורות הישנות הן USD

**לא כי נמדדו, וגם לא כי hardcoded — אלא כי backfill.**

`supabase/migrations/20260802140000_trades_currency.sql`:
```sql
add column if not exists currency text not null default 'USD';
add constraint trades_currency_check check (currency in ('USD','ILS'));
```

- העמודה נולדה **2026-08-02**.
- **55/60 עסקאות נוצרו לפני כן** (הראשונה 2025-09-03 11:30, האחרונה שלפני המיגרציה
  2026-08-06 13:49:55 — זו כבר אחרי).
- ⛔ **ה-CHECK constraint מגביל ל-`('USD','ILS')` בלבד** — נייר ב-EUR או GBP אינו
  ניתן לרישום כלל, גם אחרי שנתקן את השורש.

## §4 — מניות ישראליות: אגורות מול שקלים

### א. מה מחזיר הספק

ת"א מצטטת ב**אגורות** (1/100 ש"ח). המערכת אינה קוראת מחיר ת"א מספק כלל —
Finnhub/TwelveData אינם מכוסים לניירות המספריים הללו — ולכן **המחיר הוזן ידנית
כפי שנראה במסך המסחר: באגורות.** המערכת שמרה אותו כמספר חשוף וטיפלה בו כיחידות.

### ב. הבאג של יצחק — התיקון חי, אבל צר

`src/import/brokerProfiles.js:139-150`:
```js
const unitDivisor = (value, qty, rate) => {
  if (value == null || qty == null || rate == null) return null;
  const gross = Math.abs(qty) * Math.abs(rate);
  if (!Number.isFinite(gross) || gross === 0) return null;
  const r = Math.abs(value) / gross;
  if (closeTo(r, 1)) return 1;
  if (closeTo(r, 0.01)) return 100;
  return null;
};
```
עם `FX_MIN = 2` · `FX_MAX = 6` · `closeTo(v, target, tol = 0.02)`, ופרופיל IBI
שגוזר מטבע מ-`שווי כולל בש"ח` / `שווי במטבע`.

| שאלה | תשובה |
|------|-------|
| התיקון חי? | ✅ כן, בקוד ופעיל |
| מכסה מה? | **רק מסלול פרופיל ברוקר** — דורש value + qty + rate באותה שורה |
| מכסה רישום ידני? | ⛔ **לא** |
| מכסה CSV גנרי? | ⛔ **לא** — אין את שלושת השדות |

**13 העסקאות שנמצאו כאן נכנסו במסלול שהתיקון אינו מכסה.**

### ג. למה 100× מסוכן יותר מ-3×

פי 3 מרגיש חשוד. פי 100 על **מחיר בודד** נראה סביר לחלוטין — `440016` ב-1,850
אגורות (₪18.50) נראה כמו מניה של $1,850? לא. נראה כמו מניה של 1,850 יחידות
כלשהן, וזה בדיוק הטווח שבו מניות נסחרות. הטעות מתגלה רק בסכימה מול ההון —
ואף מסך אינו מציג את הסכימה הזו.

## §5 — ההמרה והכיוון שהוכרע

### א. הכיוון

> מחיר נייר הערך **תמיד** במטבע המסחר שלו, ⛔ ללא יוצא מן הכלל. העדפת החשבון
> משנה **רק** את המטבע שבו נמדד הכסף — המרה אחת, ⛔ בלי לגעת במחיר הנקוב.
