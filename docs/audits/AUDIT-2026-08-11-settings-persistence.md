### ⚠️ ההשערה שבפרומפט — **מופרכת כשורש**

> "OnboardingScreen.jsx:279 כותב ל-localStorage בלבד, והכתיבה ל-DB
> (SwingEdge_App.jsx:1660-1684) חסומה על hydratedRef."

**שתי העובדות נכונות. המסקנה מהן אינה.**

- ✅ `OnboardingScreen.jsx:279` אכן כותב ל-localStorage בלבד. מדויק.
- ✅ `SwingEdge_App.jsx:1662-1686` (הפרומפט אמר 1660-1684) אכן חסום על
  `hydratedRef`. מדויק.
- ❌ **אבל `hydratedRef` אינו החוסם בפועל.** `hydratedRef.current = true`
  נקבע ללא תנאי בסוף `hydrate()` (שורה 1650), וגם במסלול המוקדם של בלוב
  ריק (שורה 1595). הוא יכול להישאר `false` רק בשלושה מקרים:

  1. האפקט לא רץ כלל — `!isSupabaseConfigured || !supabase || !authUser?.id`

  2. `cancelled` נעשה `true` לפני שורה 1650 — כלומר unmount או החלפת

  3. `hydrate()` זורק לפני שורה 1650 — **לא אפשרי**: גם `loadSettings` וגם

- ❌ **וההוכחה האמפירית מכריעה: 32/34 מהשורות נושאות `onboarding.completed
  = true`.** אם `hydratedRef` היה חוסם את כתיבת האונבורדינג, המספר הזה היה
  אפס. המסלול עובד.

### הממצא שמסביר איך כל שורה נולדה

## §5 · ממצא נלווה (§11) — כשל שקט ב-`upsertBlob`

⛔ לא תוקן. מדווח בלבד.

```js
// src/lib/userSettings.js:75-85
async function upsertBlob(userId, blob, client) {
  if (!client) return;
  try {
    await client.from(TABLE).upsert({ ... });   // ← אין destructuring של error
  } catch (e) {
    console.error("userSettings: upsert failed", e);
  }
}
```

`supabase-js` **אינו זורק** על שגיאת RLS או הפרת אילוץ — הוא מחזיר
`{ data: null, error: {...} }`. ה-`try/catch` תופס רק כשלי רשת. **שגיאה
מוחזרת נזרקת לפח בשקט.**

זה בולט במיוחד כי שאר המודול **כן** בודק: `loadSettings` (שורה 94) ו-
`migrateFromLocalStorage` (שורה 145) שניהם עושים `const { data, error } = ...`.
גם `tradeWrite.js:39` עושה זאת, ו-`tradeWrite.js:237` נושא הערה על בדיוק
התקלה הזו בעבר.
