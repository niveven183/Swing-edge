### 🔴 F1 — המלכודת המרכזית

```js
// src/utils.js:43
export const realizedDayKey = (trade) => localDayKey(trade?.closedAt || trade?.date);
```

לעסקה **פתוחה**: `closedAt` הוא `null`, אבל `date` (יום הכניסה) **קיים** ⇒ הפונקציה מחזירה את **יום הכניסה**.

`accountAmount` (`useFxRates.js:175`) מעבירה את הערך הזה כ-`dateKey`:

```js
const { value, reason } = convert(amount, from, displayCurrency, table, realizedDayKey(trade));
```

⇒ שימוש חוזר ב-`accountAmount` לעסקה פתוחה ימיר בשער **יום-הכניסה**, ⛔ לא spot.

**והכשל שקט לחלוטין:** `fxDayKeys = realizedDayKeysOf(realTrades)` (`:1988`) רץ על **כל** `realTrades` — כולל הפתוחות — ולכן `byDay` **מכיל** את יום הכניסה. אין `null`, אין `reason`, אין `—`. רק מספר סביר ושגוי, שנע ככל שהפוזיציה מוחזקת זמן רב יותר.

⇒ ⛔ **`accountAmount` ⛔ אינה ניתנת לשימוש חוזר כפי שהיא.** נדרשת הכרעה נפרדת שמעבירה `dateKey` **חסר** במפורש.

## 1.4 43 משתמשי הדולר — הוכחת no-op

**נמדד:** `PAPER_BASE = "USD"` (`instrumentCurrency.js:165`).

עבור משתמש שבו `accountCurrency === "USD"`:

```
useFxRates("USD", "USD", …)  →  base === quote  →  status: "identity", table: null   (useFxRates.js:59)
```

⇒ אם השער נבנה כ**קיצור-דרך ברמת המצרף**:

```
accountCurrency === PAPER_BASE  ⇒  openPnL מוחזר כפי שהוא, ⛔ ללא נגיעה
```

הביטוי ⛔ אינו תלוי בנתונים כלל ⇒ **byte-identical, מוכח סטטית.** ✅

### ⚠️ אזהרה — הדרך השנייה ⛔ אינה byte-identical

אם התיקון ינותב במקום זאת **פר-עסקה** דרך `deriveInstrumentCurrency`, עסקה פתוחה עם טיקר **מספרי** (`numeric_ticker` → `AMBIGUOUS`), ללא טיקר, או טיקר לא-מזוהה תחזיר `isAggregatable === false` ⇒ `refuse("unverified_instrument")` ⇒ העסקה **תצא** מ-`openPnL`, בעוד שהיום היא **נספרת גולמית**.

⇒ ⛔ אין להוכיח no-op בדרך הזו בלי `SELECT` שמראה `0` עסקאות פתוחות בעלות טיקר לא-אלפביתי. **הקיצור ברמת המצרף מייתר את השאילתה** ולכן הוא הדרך המומלצת.

### 🔴 F2 — הפרכת הנחה בפרומפט וב-`B-119`
