## Q1 · האם GitHub מסיר cron תת-יומי בריפו ציבורי או בחשבון חינמי?

### 1.1 · המתועד — ⛔ **אין כלל כזה**

מדיניות GitHub על `schedule` (docs · "Events that trigger workflows"):

1. **המרווח המינימלי הוא 5 דקות.** `20,50 * * * *` = מרווח 30 דקות ⇒ **חוקי, בהפרש ×6.**
2. `schedule` **מתעכב** בעומס: *"The `schedule` event can be delayed during periods of
   high loads of GitHub Actions workflow runs. High load times include the start of
   every hour."* ⇒ ההמלצה לתזמן **מחוץ** לתחילת השעה — `:20`/`:50` כבר עומדים בזה.
3. 🔴 *"If the load is sufficiently high enough, **some queued jobs may be dropped**."*
   ⇒ **נשירה מתועדת במפורש** — ⛔ אבל ⛔ **בלי סף, בלי שיעור, ובלי תלות בתדר**.
4. **השבתה אוטומטית אחרי 60 יום ללא פעילות** — חלה על ריפו **ציבורי**. ⛔ **⛔ לא חלה
   כאן:** `pushedAt = 2026-08-29T15:53:30Z`, וההשבתה מבטלת **לגמרי** ⛔ ולא מדללת.

⇒ 🔴 **⛔ אין ולו כלל מתועד אחד** שמסיר, מדלל או מקצץ cron **לפי תדר** בריפו ציבורי או
בחשבון חינמי. מה שמתועד הוא **עיכוב לפי עומס** + **נשירה בעומס גבוה**, ושניהם
⛔ אינם תלויי-תדר בניסוחם.
