**אם תאשר, אריץ את ה-`SELECT` הבא כפי שהוא** (read-only, ⛔ אפס כתיבה):

```sql
-- מונה: משתמשים שנושאים לפחות ליטרל אחד מ-SCANNER_DATA בזוג (ticker, price)
-- מכנה: כל שורות user_settings שיש להן watchlist כמערך
-- אוכלוסייה: public.user_settings
WITH seed(ticker, price) AS (
  VALUES ('NVDA',142.30),('PLTR',97.80),('AVGO',221.50),('META',618.00),
         ('AMD',118.40),('MSTR',334.00),('SMCI',48.20),('TSLA',278.50)
),
rows_with_wl AS (
  SELECT user_id, settings->'watchlist' AS wl
  FROM public.user_settings
  WHERE jsonb_typeof(settings->'watchlist') = 'array'
),
hits AS (
  SELECT DISTINCT r.user_id
  FROM rows_with_wl r
  CROSS JOIN LATERAL jsonb_array_elements(r.wl) AS it
  JOIN seed s
    ON s.ticker = (it->>'ticker')
   AND (it->>'price') IS NOT NULL
   AND ROUND((it->>'price')::numeric, 2) = s.price
)
SELECT (SELECT count(*) FROM hits)          AS contaminated_users,
       (SELECT count(*) FROM rows_with_wl)  AS users_with_watchlist,
       (SELECT count(*) FROM public.user_settings) AS user_settings_rows;
```

שאילתת עומק נלווית — **כמה ליטרלים** לכל משתמש (מודדת אם המשתמש נגע ברשימה
בכלל):

```sql
SELECT r.user_id,
       count(*) FILTER (WHERE s.ticker IS NOT NULL) AS seed_literals,
       jsonb_array_length(r.wl)                     AS watchlist_len
FROM rows_with_wl r
CROSS JOIN LATERAL jsonb_array_elements(r.wl) AS it
LEFT JOIN seed s
  ON s.ticker = (it->>'ticker')
 AND ROUND((it->>'price')::numeric, 2) = s.price
GROUP BY r.user_id, r.wl
ORDER BY seed_literals DESC;
```

⚠️ **מגבלת השאילתה, מוצהרת:** היא מזהה **התאמה מדויקת לליטרל**. משתמש
שמחיר אמיתי שלו התלכד ל-`142.30` ייספר כמזוהם (false positive), ומשתמש
שהליטרל שלו נדרס בערך אמיתי ⛔ לא ייספר. **⇒ המספר הוא חסם, ⛔ לא ספירה
מדויקת** — וזו בדיוק ההשלכה של `R-1`: **⛔ אין חותמת ⇒ ⛔ אין מדידה מדויקת
אפשרית בדיעבד.** ⚠️ זה ⛔ אינו פגם בשאילתה; זה הממצא.
