## 2 · ממצא ① — ⑥ הוא no-op, ו⑦ ⛔ יכול להתקיים

`markerVerdict` (`scripts/registry-test.mjs:~559`) מכריע בסדר הזה:

```js
const p = strip(cell);
for (const m of p.matchAll(EYE)) {
  if (!denied(p, m.index, m[0].length)) return { ok: true, why: `סמן מפורש: ${m[0]}` };
}
if (DENIED.test(p)) return { ok: false, why: "הכחשה מפורשת של אימות-עין/מקור" };
```

**ה-`return` החיובי יושב בתוך לולאת `EYE`, כלומר `DENIED` ⛔ נבדק כלל** ברגע
שנמצא סמן אחד שאינו נשלל ע"י `denied()` בחלון ±90. נמדד על התא הניסיוני של ⑦:

```
⑦ תא ניסיוני ששולל את הסמן:
   ⟪⛔ «אומת-מקור» — הבדיקה טרם נעשתה⟫
   markerVerdict כיום → ok=true  (סמן מפורש: אומת-מקור)
   DENIED החדש (עם ⛔) מתאים לתא?  true
   markerVerdict מחזיר ok=true **בתוך לולאת EYE**, ⛔ לפני שהווטו נבדק כלל:  true
   ⇒ הוספת ⛔ ל-DENIED לבדה = no-op. ⛔ אין מוטנט שיכול לצבוע אותה אדום.
```

⚠️ **הווטו של `DENIED` אינו מת — הוא פשוט ⛔ מכוסה ע"י ⑦.** הוא יורה רק כשאין
בתא **שום** סמן שעבר את `denied()`. הרחבתו ל-`⛔` משנה את התשובה באפס תאים,
קיימים או ניסיוניים. ⇒ **אסרציה שנוספה על בסיס ⑥ לבדה ⛔ נצפית אדומה לעולם**,
וזו בדיוק הגדרת «אסרציה שאינה קיימת» (‹R-3›).

> **הערה על סדר הבדיקות — ⛔ ניתן להיפוך «בדרך».** ההערה ב-`:606-610` מקפיאה
> את הסדר הזה במפורש (`B-162`), ו-fixtures 12/13 מקפיאים את שני הכיוונים.
> הזזת הווטו מעל הלולאה היא **הכרעת עיצוב**, ⛔ תיקון.
