## D2 — `B-001`, שני חצאים שאסור לערבב

### (א) `Failure Alert` אינו ברשימת עצמו

**נמדד:** `failure-alert.yml:10` מונה 11 שמות. `"Failure Alert"` ⛔ אינו ביניהם.

⚠️ **וזה ⛔ אינו פתיר בתוך הקובץ:** גם אילו נוסף — GitHub ⛔ אינו מפעיל
`workflow_run` רקורסיבית מריצה שמקורה ב-`workflow_run`. הריפו כבר יודע זאת
ומתעד זאת פעמיים בנוסח כמעט זהה:

- `watchdog.yml:100` — «self: watched by fleet-daily.yml instead — **an agent cannot report its own death**»
- `fleet-daily.yml:222-224` — «Mutual watch: … **An agent cannot report its own death** — watchdog listing itself in [its own table] …»

🔴 **אבל תבנית `fleet-daily`→`watchdog` ⛔ אינה חלה כאן, וזו הנקודה:**

| | `Watchdog` | `Failure Alert` |
|---|---|---|
| טריגר | `schedule` — יומי | `workflow_run` — לפי דרישה |
| "לא רץ 24ש'" משמעו | 🔴 **מת** | ✅ **שבוע בריא** |
| האם היעדר-ריצה הוא אות? | **כן** | ⛔ **לא** |
| האם בדיקת חיוּת תקפה? | ✅ כן (`fleet-daily:221`) | ⛔ **לא — חסרת-הבחנה** |

📌 **`fleet-daily` יכול לשמור על `watchdog` רק משום ש-`watchdog` מתוזמן.**
היעדר ריצה של סוכן מתוזמן הוא **מדיד**; היעדר ריצה של סוכן תגובתי **אינו**.
⇒ **העתקת התבנית ל-`Failure Alert` תייצר שומר שמדווח "🔴 מת" בכל שבוע שקט,
או — אם ירככו את הסף — שומר שירוק תמיד. שניהם `R-4`.**

**⇒ המסקנה: (א) פתיר אך ורק בבדיקה אקטיבית (D6).**

### (ב) `watchdog.yml:101` מדלג עליו בהגדרה

**נמדד** — `watchdog.yml:98-105`:

```bash
for f in .github/workflows/*.yml; do
  base="$(basename "$f")"
  [ "$base" = "watchdog.yml" ] && continue
  if grep -qE '^\s*schedule:\s*$' "$f" && [ -z "${MAXAGE[$base]+x}" ]; then
    consistency_lines="…⚠️ workflow מתוזמן לא מנוטר: $base"
```

התנאי הוא `grep 'schedule:' && לא-בטבלה`. `failure-alert.yml` הוא `workflow_run`
בלבד ⇒ ה-`grep` נכשל ⇒ **הבדיקה שנועדה לתפוס "workflow לא מנוטר" מדלגת עליו
בהגדרה.** ✅ טענת `B-001` מאוששת מילה במילה.

⚠️ **אבל שים לב מה זה ⛔ אינו:** הבדיקה הזו ⛔ אינה שומר-כשל — היא **שומר-סחיפת-טבלה**.
היא בודקת שהטבלה תואמת לקבצים, ⛔ לא שהסוכנים חיים. גם אילו כללה את
`failure-alert.yml`, כל שהייתה עושה הוא לדרוש ערך `MAXAGE` — כלומר לייצר
בדיוק את בדיקת-החיוּת חסרת-ההבחנה מ-(א).

📌 **(ב) הוא באג אמיתי בשומר-הסחיפה, ⛔ ואינו הדרך לתקן את (א).**
ערבוב שני החצאים הוא איך שנולד תיקון שנראה שלם ומשאיר את החור פתוח.

## D4 — `B-018`: האם ההצהרה ב-`failure-alert.yml:6-7` נכונה?

🔴 **מה שההצהרה ⛔ אינה מכסה — והיא נוסחה בלי הסתייגות:**

| מצב | האם `always()` עוזר? | מה נשאר |

### ⇒ פסק D4 — `S8γ` מאושש

📌 **ההערה מצהירה על תכונה אוניברסלית («self-alarms on its own failure
condition») בעוד שהתכונה חלה על תת-קבוצה בלבד — כשל-צעד בתוך job שהתחיל.**
זהו בדיוק הדפוס מ-`B-142`: **הערה שמצהירה שמצב בלתי-אפשרי, והמצב אפשרי.**

⚠️ **וחומרת השארית גבוהה מהממוצע דווקא כאן:** הרשת היחידה שנותרת היא
`Watchdog` בסף **840ש'** — **איחור-גילוי ~124ש' (5.2 ימים)** לפי D3, וזאת
**רק אם `Watchdog` עצמו חי**. עבור גיבוי שנבדק **פעם בחודש**, המשמעות היא
