## 2 — F3 / `B-454`: המכניזם (נמדד, ⛔ הנחה)

מקור: ג׳וב `prod` של run `40909046913` (29.10), pixel7 `b · en`, **8.4s**:

```
Error: "route.fetch: Request context disposed.  … → GET …/rest/v1/user_settings?select=settings%2Cupdated_at&user_id=eq.1ad72482…" while running route callback.
Consider awaiting `await page.unrouteAll({ behavior: 'ignoreErrors' })` before the end of the test to ignore remaining routes in flight.
> 147 |         const res = await route.fetch();
```

1. **הבדיקה עצמה עברה** — אין אסרציה אדומה לצד השגיאה (`83 passed · 1 failed`, הכישלון הוא השגיאה הזו בלבד). `b · en` הוא הטסט **האחרון** בקובץ ב-`afterAll`-adjacent: `finally { await app.ctx.close() }` (`cents.spec.js:599`).
2. **ה-route עונה לכל כתיבה `201 []`** (`cents.spec.js:146`). תחת CAS (`B-435`, נחת 18.10) תשובה ריקה = «קונפליקט» ⇒ האפליקציה שולחת **GET נוסף**. ה-GET הזה הוא בקשה שה-handler מבצע דרך `route.fetch()` (`:147`) — **רשת חיה לפרודקשן, 100–1000ms**. אם `ctx.close()` נקרא בזמן שהבקשה באוויר ⇒ `Request context disposed`.
3. **הסיבה ש-`6/8` ולא `1/8`:** מאז CAS, כל כתיבת הגדרות בטסט (סגירת עסקה כותבת הגדרות) מייצרת GET שני. לפני CAS (`7c368ec` 20.10) — ירוק.
4. **סיווג: (ב) מירוץ teardown ב-harness.** ⛔ באג מוצר: האפליקציה מתנהגת נכון (קונפליקט ⇒ קריאה מחדש).

⚠️ **הצעת Playwright עצמה — `unrouteAll({ behavior: 'ignoreErrors' })` — ⛔ מותרת כאן:** זו בדיוק בליעת שגיאה (`CLAUDE.md` §2, «אפס כשל שקט»). ההתנהגות הנכונה: **`behavior: 'wait'`** — מחכה ל-handlers בטיסה לסיים. (`ignoreErrors` ⇒ היה מסתיר גם GET שנכשל באמת.)

**אתרי `route.fetch` נוספים (אותה מחלקה, ⛔ אותה סגירה):** `overlay.spec.js:65` · `width.spec.js:77` · `tests/lib/eyeTools.js:357`. ⇒ **helper אחד** (R-6), ⛔ תיקון נקודתי ב-`cents.spec.js`.
