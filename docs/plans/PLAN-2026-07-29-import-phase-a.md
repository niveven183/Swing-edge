## אבחון — ממצאים מאומתים

### 1. חד-מילי אינו משתתף ב-fallback
[`synonyms.js:54`](src/import/synonyms.js:54) — `if (synTokens.length > 1 && …)`.
הוכחה בהרצה על הקוד הנוכחי:

```
"שער ביצוע" → null      "סוג פעולה" → null      "תאריך הוראה" → null
"שער עלות ממוצע" → null  "מס' נייר / סימול" → null (normKey: "מס נייר סימול")
```

הוספת `"שער"` בלבד לא תפתור כלום. חייבים גם צירופים רב-מיליים וגם שינוי בלוגיקה.

### 2. הקדימות נקבעת לפי סדר הכרזת השדות — לא לפי ספציפיות
לולאת ה-fallback רצה על `Map` בסדר הכנסה: `ticker → side → entry → exit → shares → date →
exitDate → stop → target`. בשילוב עם `"l/s"` שמתנרמל ל-`"l s"` (שני טוקנים בני תו אחד),
זהו **באג חי היום**:

```
"stop loss price" → side ✗    "long position size" → side ✗
"total shares sold" → side ✗   "last sale price" → side ✗
```

כותרות עבריות ניצלות רק במקרה — אין בהן אותיות לטיניות.

### 3. שתי עמודות ticker — ההכרעה לפי סדר בקובץ
[`detectColumns.js:66-71`](src/import/detectColumns.js:66) — `assign` הוא first-wins.
באלטשולר `"שם נייר"` (שם חברה) מקדים את `"מס' נייר / סימול"` (הסימבול האמיתי), ולכן
ה-ticker יהיה טקסט מת ולא סימבול שניתן להצליב מול מחיר חי.

### 4. עובדות תומכות
- `normKey` מפשיט גרש **ASCII** בלבד; גרש עברי `׳` ומסולסל `’` שורדים. ה-fallback משתמש
  ב-`includes` (תת-מחרוזת), ולכן טוקן `"מס"` נמצא גם ב-`"מס׳"` וגם ב-`"מספר"` — מכוסה.
- ממשק מיפוי ידני **קיים** ([`ImportJournalModal.jsx:163-252`](src/components/ImportJournalModal.jsx:163)):
  dropdown לכל עמודה, אזהרה על שדות חובה חסרים, "המשך" חסום עד שכולם ממופים. אין דחייה שקטה.
- `colField` הוא state של קומפוננטה. **אין `localStorage`, אין מיפוי נשמר** — `applyDetection`
  דורס בכל העלאה. לכן אין מיפוי ידני קיים שהשינוי עלול לשבור.

## התוכנית

### קובץ 1 — `src/import/synonyms.js`

**א. תוספות למילון**

| שדה | להוסיף |
|-----|---------|
| `entry` | `"שער"`, `"שער ביצוע"`, `"שער עלות"`, `"שער עלות ממוצע"`, `"שער קנייה"`, `"שער קניה"`, `"מחיר ביצוע"`, `"מחיר"` |
| `exit` | `"שער מכירה"`, `"מחיר סגירה"` |
| `side` | `"סוג פעולה"`, `"סוג עסקה"`, `"סוג הפעולה"` |
| `ticker` | `"מספר נייר"`, `"מס נייר"`, `"מס' נייר"`, `"שם הנייר"` (`"סימול"` כבר קיים) |
| `shares` | `"כמות ניירות"`, `"כמות יחידות"` |
| `date` | `"תאריך ביצוע"`, `"תאריך הוראה"`, `"תאריך עסקה"` |
| `exitDate` | `"תאריך מכירה"` |

`"מטבע"` — **לא מוסיפים**. אין שדה יעד, ואומת שהוא אינו נגנב לשום שדה (`fieldForHeader → null`,
ו-pass 2 לא מסווג `₪`/`$` כתאריך או כ-side). הוספה כאן הייתה no-op מטעה.

`"מחיר"` — **מוסיפים**. הבטיחות נשענת על דירוג הספציפיות שלמטה, לא על מחסום החד-מילי:
`"מחיר יעד"` נתפס בהתאמה מדויקת שקודמת ל-fallback, וגם ב-fallback `"מחיר יעד"` (7 תווים)
מנצח את `"מחיר"` (4). זו הבדיקה המפורשת בחוזה.

**ב. שכתוב `fieldForHeader` — דירוג לפי ספציפיות**

מחליף את "הראשון-לפי-סדר-הכרזה מנצח" ב-argmax. חוזה:

1. **התאמה מדויקת** על `normKey` — קודמת לכול, ללא שינוי.
2. **fallback**: אוסף את *כל* הסינונים שכל הטוקנים שלהם מוכלים בכותרת, ובוחר את בעל
   הציון הגבוה. ציון = אורך הסינון המנורמל ללא רווחים. שובר-שוויון: מספר טוקנים, ואז
   סדר הכרזה.
3. **פסילת טוקנים מנוונים** — הכלל שמכבה את באג ה-`l/s`:
   - סינון רב-טוקני: כל טוקן חייב ≥ 2 תווים → `"l s"` נפסל.
   - סינון חד-טוקני: אורך ≥ 3 תווים → `"sl"`, `"tp"`, `"b"`, `"l"` נפסלים;
     `"buy"`, `"שער"`, `"מחיר"`, `"נייר"` מותרים.
   חד-מילי **כן** משתתף ב-fallback מעתה — זה מה שמאפשר `"total shares sold" → shares`,
   והספציפיות היא שמונעת ממנו לגנוב.
4. מייצא גם את הציון (`matchHeader(header) → {field, score}`) עבור `detectColumns`.
   התאמה מדויקת מקבלת בונוס קבוע כדי שתקדם תמיד ל-fallback.

תוצאות צפויות: `"stop loss price"` → `stop` (דרך `"stop price"`, 9) · `"total shares sold"`
→ `shares` · `"long position size"` → `shares` · `"שער ביצוע"` → `entry`.

### קובץ 2 — `src/import/detectColumns.js`

**ג. בחירת עמודה לכל שדה לפי חוזק ההתאמה, לא לפי סדר בקובץ**

pass 1 היום הוא first-wins ([`:66-77`](src/import/detectColumns.js:66)). במקום זה: לאסוף את כל
המועמדות לכל שדה עם הציון מ-`matchHeader`, ולבחור את המנצחת.

**שובר-שוויון ל-`ticker` לפי תוכן.** `"שם נייר"` (התאמה מדויקת) יגבר על `"מס נייר סימול"`
(fallback) בציון כותרת בלבד — ולכן, כששתי עמודות מתחרות על `ticker`, מכריעים לפי הערכים:
עמודה שרוב ערכיה נראים כסימבול שוק (`/^[A-Z][A-Z0-9.\-]{0,5}$/`) מנצחת.

זו הרחבה של עיקרון שכבר קיים בקובץ — pass 2 כבר מכריע `date`/`side` לפי תוכן — ומשתמשת
מחדש ב-`colValues` וב-`majority` ([`:29-36`](src/import/detectColumns.js:29)) ללא כלים חדשים.
`PLTR`/`NFLX` עוברים; `"META PLATFORMS INC"` ו-`"דיסקונט א"` נכשלים. זהו גם הנימוק העסקי:
סימבול נכון = מחיר חי וגרף; שם חברה = טקסט מת.

חל **רק** כשיש יותר ממועמדת אחת ל-`ticker`. בפיקסצ'ר יחיד-עמודה — אין שינוי.

## §9 — נוהל ותנאי האישור

התוכנית אושרה ע"י ניב ב-2026-07-29, עם שלושה תנאים מחייבים:

1. **בדיקת ה-baseline היא תנאי חוסם.** אם אחד מ-6 הפיקסצ'רים הקיימים זז —
   עצור, דווח, אל תמשיך. **אין לעדכן את הערך הצפוי כדי שיעבור.** בדיקה
   שמותאמת בדיעבד לקוד החדש היא בדיקה מתה. העובדה שכל הפיקסצ'רים הם
   התאמה מדויקת ולכן ה-fallback אינו רץ עליהם — נכונה, אך אין להסתמך
   עליה במקום הרצה בפועל.
2. **סייג ההיוריסטיקה של `ticker` מתועד בקוד עצמו**, ליד ה-regex, ולא רק
   כאן: זו היוריסטיקה מכוונת לשוק האמריקאי עם גבול ידוע (ניירות ישראליים
   מספריים כגון `1159250` אינם נתפסים), ולא ניסיון כושל לתפוס הכול.
3. **`"מחיר"` מוצדק ע"י בדיקת הקדימות בלבד.** אם היא אינה עוברת — להסיר את
   `"מחיר"` מהמילון ולדווח, ולא לרכך את הבדיקה.
