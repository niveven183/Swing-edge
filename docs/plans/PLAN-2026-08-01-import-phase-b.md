### ב. איך נבחרת שורת הכותרת היום

`parseFile.js:19` — **השורה הראשונה שאינה ריקה**, תמיד. אין פרמטר, אין עקיפה.
ההנחה בפרומפט ("שורה 0 תמיד") נכונה מעשית, אבל **הבעיה חמורה מהמנוסח**, בגלל
`parseFile.js:20`:

```js

const width = headers.length;      // ← הרוחב נגזר משורת הפתיח
```

`width` מקבע את מספר העמודות של **כל** השורות. הקובץ האמיתי של IBI מדגים זאת
בצורתו הרכה: שורות 1–3 ריקות (שורה 1 מכילה לוגו כ**תמונה**, שמתאדה בייצוא),
ולכן `rowsRaw[0]` היא שורה 4 — `["תנועות היסטוריות","","",…]`. פלט מדוד על
הקובץ האמיתי (317 שורות נתונים):

```

mapping = {"date":7}
counts  = {"total":317,"valid":0,"duplicates":0,"rejected":317}
```

**זו חוויית המשתמש בפועל: אפס עסקאות מתוך 317 שורות.** אילו שורת הפתיח לא

מוכיחים את אותה מסקנה: **תיקון שרץ *אחרי* `matrixToTable` אין לו על מה לעבוד.
הפרופיל חייב לרוץ על המטריצה הגולמית.** זו האילוצה הארכיטקטונית של השלב.

### ד. `side` היום

`normalizeSide` (`synonyms.js:87`) מקבל טקסט בלבד. פלט מדוד:

| קלט | פלט | | קלט | פלט |
|---|---|---|---|---|
| `"קניה"` / `"קנייה"` | `LONG` | | `"דיבידנד"` / `"דיבדנד"` | `null` |
| `"מכירה"` | `SHORT` | | `"המרת מט״ח"` | `null` |
| `"קניה חול מטח"` | `LONG` | | `"משיכה"` / `"הפקדה"` | `null` |
| `"מכירה חול מטח"` | `SHORT` | | `"מתנה"` | `null` |
| `"Buy"` / `"Sell"` | `LONG` / `SHORT` | | `"-5"` | `null` |
| **`"מכר"`** | **`null`** ⚠️ | | | |

`"מכר"` (צורה נפוצה בדוחות) אינו נתפס: הענף בודק `k.includes("מכיר")`.
**נבדק על הצורות המורכבות האמיתיות של אלטשולר — כל שש נפתרות נכון היום.**

**כמות שלילית — שלוש הצורות נדחות:**

```
qty=-19  -> REJECT no_qty
qty=19-  -> REJECT no_qty     ← הצורה שבפרומפט
qty=(19) -> REJECT no_qty     ← num() מחזיר -19, ואז shares<=0
```

`num()` דווקא מפרש `(19)` כ-`-19` נכון, אבל `19-` (סיפרה ואז מקף) מתפרק:
`s.replace(/[^\d.\-]/g,"")` משאיר `"19-"`, ו-`Number("19-")` הוא `NaN` → `null`.
**שלוש צורות, שלוש דחיות, אף אחת לא הופכת ל-SHORT.**

#### ד2. הטאוטולוגיה של F4 — האימות המדויק

`normalizeRow:94-101`:

```js
let side = normalizeSide(cell("side"));
if (!side) side = inferSide(entry, stop, target);        // :95
if (stop != null && stop > 0) {
  const v = validateTradeInputs(entry, stop, target, side);   // :99
```

מדדתי את שני הענפים בנפרד — **הטאוטולוגיה חלקית, לא מלאה**:

| מצב | `inferSide` בוחר לפי | האם `validateTradeInputs` יכול להיכשל? |
|---|---|---|
| `stop` בלבד, בלי `target` | הסטופ | **לא לעולם** — טאוטולוגיה מלאה |
| `target` קיים | היעד | כן — הסטופ נבדק מול ציר עצמאי |
| **אין `stop` כלל (קובץ ברוקר)** | — | **הבדיקה מדולגת כליל** (`:98`) |

השורה השלישית היא המקרה של **שני** קבצי הברוקר האמיתיים — לאף אחד מהם אין
עמודת סטופ — ולכן `inferSide(entry, 0, 0)` נופל ל-`return "LONG"` (`utils.js:58`)
ואף אחד לא בודק דבר.

**בפרופילים זה מתהפך:** `side` יגיע ממקור עצמאי, ולא מהגיאומטריה. מרגע זה
`validateTradeInputs` חוזר להיות בדיקה אמיתית. **זו הסיבה שהפרופיל הוא גם תיקון
נכונוּת ולא רק תיקון קליטה.**

### `detect()` — טביעת אצבע על מערך העמודות המלא

**החלטה:** הזיהוי דורש **≥8 מתוך 11** מחרוזות הכותרת של IBI, או **≥9 מתוך 13**
של אלטשולר, בהתאמה מדויקת ובלי תלות בסדר.

הנימוק אינו "כמה שיותר בטוח" אלא ספציפי: המחרוזות הבודדות **אינן** ייחודיות.
`שם נייר` · `מספר נייר` · `פעולה` · `שער עלות ממוצע` · `תאריך הוראה` כולן
מופיעות ב-`ibi-style.csv` הסינתטי משלב א' (6 עמודות), ולכן טביעת אצבע של
3 מחרוזות הייתה **בולעת פיקסצ'ר קיים** ומשנה את תרחיש 7 — בדיוק סוג ההשפעה
הצדדית שהשלב הזה אמור למנוע. מערך של 11/13 עמודות הוא חתימה שקובץ גנרי או
סינתטי אינו יכול לפגוע בה במקרה.

**נורמליזציה לפני ההשוואה:** `U+201D` (`”`), `U+05F4` (`״`) ו-`U+0022` (`"`)
מנורמלים לצורה אחת, ורצפי רווחים מצטמצמים. בלי זה `שווי כולל בש”ח` לא ייתפס
בשום מכונה שמקלידה גרש רגיל.

### שינוי מינימלי ב-`parseFile.js` — חשיפת המטריצה הגולמית

מסקנת §0.ב: הפרופיל חייב לראות את המטריצה לפני הריבוע. שתי תוספות **אדיטיביות
בלבד**:

1. `matrixToTable(matrix, headerIdx = null)` — `null` = ההתנהגות הקיימת, מילה במילה.
2. הערך המוחזר מ-`parseCSV`/`parseXLSX` מקבל שדה נוסף `matrix`.

אין שינוי בחתימה, אין שינוי בהתנהגות למי שלא מעביר `headerIdx`. **המסלול הגנרי
מחזיר בייט-אחד-לאחד את מה שהוא מחזיר היום** — וזה בדיוק מה ששער ה-baseline מוכיח.

### זיהוי שורת הכותרת — דינמי · **הסף אומת מול שני הקבצים**

`headerRow(matrix)` = **השורה הראשונה שבה ≥4 תאים מחזירים `matchHeader` לא-null,
ולפחות 3 שדות קנוניים שונים**.

הסף הועמד למדידה על שני הקבצים האמיתיים (`cells` / `fields` לכל שורה):

| קובץ | שורות פתיח | השורה שעוברת | מרווח |
|---|---|---|---|
| IBI | מקסימום `1/1` (שורות 6–7: "תאריך הפקת הקובץ") | **שורה 11 — `7/5`** | פי 7 בתאים |
| אלטשולר | מקסימום `1/1` (שורות נתונים) | **שורה 1 — `8/6`** | פי 8 בתאים |

**מסקנה: הסף עובר כפי שהוא. אין צורך בכוונון.** שורת נתונים בודדת מגיעה
ל-`1/1` לכל היותר, כי `matchHeader` מותאם לכותרות ולא לערכים. המרווח בין `1`
ל-`7` רחב מספיק כדי שלא יידרש כוונון עתידי לכל קובץ שנתקל בו.

### `rowFilter` — whitelist, לא blacklist · **הרשימות מהקבצים האמיתיים**

| פרופיל | נשמר (עסקה) | מסונן ומדווח |
|---|---|---|
| IBI | `קנייה` · `מכירה` | 10 הסוגים הנותרים (§0.ה) |
| אלטשולר | `קניה חול מטח` · `קניה רצף` · `קניה שח` · `מכירה חול מטח` · `מכירה שח` · `מכירה רצף` | `משיכה` · `הפקדה` · `דיבדנד` · `ריבית מזומן בשח` · `העברה מזומן בשח` |

ההתאמה היא **תחילית מנורמלת** (`קניה`/`קנייה`/`מכירה` בתחילת הערך), לא רשימה
סגורה של צירופים — כדי ש`קניה מעו"ף` שיופיע מחר לא ייפול בין הכיסאות. שורה
שאינה עונה לאף תחילית **מסוננת ומדווחת** — כלומר עדיין נכשל סגור.

**וכדי שהסגירה לא תהיה שקטה** (§2): כל שורה שסוננה נספרת ב-`skipped` **עם סוג
הפעולה שלה**, ומוצגת במסך הסקירה — ראה "המונה הגלוי" למטה.

### `sideFrom` + חוזה הכמות

| פרופיל | מקור ה-`side` | נימוק מדוד |
|---|---|---|
| IBI | **סימן הכמות** | עקבי 243/243 (§0.ה) |
| אלטשולר | **טקסט "סוג פעולה"** דרך `normalizeSide` | הכמות חיובית תמיד, גם במכירות — הסימן חסר-מידע |

**אינווריאנטה נלווית, מפורשת:** כשהסימן נצרך ככיוון, הוא **אינו** נקרא שוב
ככמות — `shares = Math.abs(shares)`. אחרת המכירה תמשיך ליפול על `shares <= 0`
(87 המכירות ב-IBI). תיקון נלווה: `num()` יטפל בצורת הסיפא `19-` (היום `NaN`).

### החיבור ל-`normalizeRow` — בלי לגעת במסלול הגנרי

`normalizeRow` יקבל `opts.sideResolver` אופציונלי (`row -> side | null`):

* **`opts.sideResolver` חסר** → הקוד רץ בדיוק כפי שהוא רץ היום. אפס דלתא.
* **קיים ומחזיר `side`** → אותו `side` גובר על `inferSide`, והכמות נלקחת ב-`abs`.

זו התוספת היחידה ל-`normalizeRow`. `inferSide` נשאר fallback למסלול הגנרי.
