### 1.1 מה ה-baseline מוכיח

**A — חוזה הרגרסיה.** קריאה מלאה עובדת: entry מחושב דטרמיניסטית
(4.39/0.05871 ו-12.16/0.16263 מתכנסים), stop/target = entry ± delta,
confidence 95 (85 + 5 התכנסות + 5 הסכמה עם Vision). **אסור שיזוז בבית אחד.**

**B — הבאג, לכוד במבחן.** `confidence: 85` עם שלושה `null`. זהו בדיוק הקלט
שמייצר "OCR ✓ 85%" ירוק על טופס ריק. אישור מספרי לטענת האודיט §2ב.

**C — מתדרדר נכון כבר היום.** `confidence: 0`, `ticker: null`. האודיט §2ד צדק:
`max_tokens` אינו אשם. אף תיקון לא אמור לגעת בזה.

**D — ממצא חדש שאינו באודיט.** `stopDelta` **שלילי** בלונג (קריאה חסרת-פשר
לחלוטין) מחזיר **confidence 90** — השני-הגבוה בסט. הפירוט: `computeEntry`
דוחה את רגל ה-stop (`stopDelta > 0` נכשל), נופל על רגל ה-target בלבד,
`validate` תופס את ה-stop ומאפס אותו (✅), אבל `rrOk` מחזיר `true` בוואקום
(`stopDelta > 0` נכשל → השער לא יורה), ו-Vision מסכים על ה-entry → `+5`.
**התוצאה: עסקה בלי stop, עם באדג' ירוק 90%.** זהו וריאנט של F4 (`api/ocr.js`
`:458-460`, "השער לא יכול לירות בדיוק במקרה שבו הוא נחוץ").
**מחוץ להיקף** — הוקפא כדי שלא יזוז בשקט. שורה ב-⚠️ ב-STATE.

### F2 — `api/ocr.js:421-424` (השורש, קודם)

**היום:**
```js
if (parsed.hasPositionTool !== true) {
  res.status(200).json({ ...nullResult, ticker, confidence: modelConf });
  return;
}
```
`nullResult.confidence` הוא 0 (`:355`) ו**נדרס** ע"י ה-spread. `validate()`
יושב ב-`:445` — אחרי ה-`return` — ולכן **לעולם אינו נקרא במסלול הזה**.

**אחרי:**
```js
// The model's certainty here is certainty that there is NO position tool —
// it says nothing about prices, and there are none. Cap it below MIN_CONFIDENCE
// so every badge reads it as failure, but keep it non-zero: the low end still
// separates "sure there's no tool" from "could not read the image at all".
if (parsed.hasPositionTool !== true) {
  res.status(200).json({ ...nullResult, ticker, confidence: Math.min(modelConf, 25) });
  return;
}
```

**נימוק לצורה — למה קאפ ולא שדה `detected` חדש** (הפרומפט ביקש להכריע ולנמק):

| אפשרות | הכרעה |
|--------|--------|
| שדה `detected: false` חדש | ⛔ **נדחה.** הלקוח כבר מחזיק את `entry`/`stop`/`target` ויכול לגזור את מצב הזיהוי בעצמו. שדה שרת יוצר **מקור אמת שני לאותה עובדה** — בדיוק מה ש-§13 אוסר. הוא גם משאיר את ה-85 הכוזב על החוט |
| `confidence: 0` | 🟡 נשקל ונדחה. עקבי, אבל מוחק את ההבחנה בין "המודל היה בטוח שאין כלי" ל"המודל התלבט" — וזה בדיוק האות שיגיד לנו בהמשך אם האשם בפרומפט או בתמונה |
| `Math.min(modelConf, 25)` | ✅ **נבחר.** שורה אחת · אפס שינוי בחוזה · `25 < MIN_CONFIDENCE(40)` ולכן **שלושת הבאדג'ים** קוראים אותו ככשל **מיידית, עוד לפני F3** · הקצה הנמוך שורד ומזין את `confidence_bucket` |

**השפעה על ה-baseline:** תרחיש **B** בלבד — `confidence: 85` → `25`.
A/C/D אינם זזים. שורת `B` ב-`FROZEN` מתעדכנת **באותו commit**, וזו כל
מטרתו של F2. (A זז = STOP.)

### F3 — הבאדג' נגזר ממה שמולא · `App:4113` + `:5170` + `:6374`

**היום, בשלושת האתרים:** `const high = ok && confidence >= 70;` — הבאדג'
לעולם אינו שואל האם שדה כלשהו התמלא.

**אחרי — פונקציה טהורה אחת ב-module scope** (§13 אנטי-flicker), שאליה
ניגשים שלושת האתרים:

```js
// What the OCR actually contributed, independent of what the form already held.
// Derived from the response, not from the form: a value the trader typed by hand
// is not an OCR success, and a value OCR read is not a failure just because the
// manual field won the merge.
function ocrDetection(result) {
  const has = (v) => v !== null && v !== undefined;
  if (has(result.entry) && has(result.stop) && has(result.target)) return "full";
  if (has(result.entry)) return "partial";
  if (has(result.ticker)) return "ticker_only";
  return "none";
}
```

ה-state של שלושת הצרכנים מתרחב מ-`{ status, confidence }` ל-
`{ status, confidence, detection }` — **תוספת בלבד**, אף צרכן קיים לא נשבר.

הרינדור עובר לפונקציה משותפת אחת, `ocrBadge(status, confidence, detection, t)`,
המחזירה `{ tone, icon, text }`:

| מצב | תנאי | טקסט | גוון |
|-----|------|------|------|
| ✓ ירוק | `full` ∧ `confidence ≥ 70` | `OCR ✓ {conf}%` | accent |
| ~ ענבר | `full` ∧ `40 ≤ conf < 70` | `OCR ~ {conf}%` | warn |
| 🟠 חלקי | `partial` | `t.ocrPartial` | warn |
| 🟠 סימבול | `ticker_only` | `t.ocrTickerOnly` | warn |
| 🔴 כלום | `none` | `t.ocrLowConfidence` (קיים) | loss |

`processing` / `config_error` / `error` — ללא שינוי.

**⚠️ סטייה מהבקשה — מצב `partial` רביעי.** ביקשת שלושה מצבים. תרחיש D
ב-baseline מייצר entry + target **בלי stop**, ובשלושתם היה נופל היום לתוך
"✓ ירוק 90%". באדג' ירוק על עסקה חסרת-stop הוא בדיוק מחלקת הכשל שאנחנו
סוגרים. **ברירת המחדל שאבצע: כולל `partial`.** אמור מילה אם אתה מעדיף שלושה.

**נוסח `ocrTickerOnly` (5 שפות · he/en/es/pt/ar):**
> he: `זוהה סימבול בלבד — צייר כלי Long/Short על הגרף לזיהוי מחירים`
> en: `Symbol only — draw a Long/Short tool on the chart to read prices`

**נוסח `ocrPartial`:**
> he: `זוהו חלק מהמחירים — השלם את השאר ידנית`

**מובייל 406px** (סעיף הציד #3): המחרוזת החדשה ארוכה פי ~4 מ-`OCR ✓ 85%`.
המכולה היום `flex items-center gap-2 … text-[11px]` ללא `shrink-0` על האייקון
— בטקסט ארוך ה-`<svg>` נמעך. התיקון: `shrink-0` על האייקון ו-`leading-snug`
על ה-`<span>` כדי שיגלוש לשתי שורות במקום להיחתך. **מאומת בדפדפן ב-406px

### F1 — ההשקה · `App:1913-1937` (אנלייזר) + `:1883-1908` (Log New Trade)

**היום** (`:1920-1924`, ותאום מדויק ב-`:1891-1895`):

  if (f.ticker.toUpperCase() !== ticker.toUpperCase()) return f;

**אחרי — `ref` אחד לכל טופס, ממופתח לפי טיקר:**

// matches, the live quote must not fill Entry: the trader is looking at a
// chart whose entry we failed to read, and a current price in that field is

const analyzerOcrTickerRef = useRef(null);

נקבע ב-`handleAnalyzerImageUpload`, **לפני** כתיבת הטיקר לטופס (ref סינכרוני,

`result.entry == null` בלבד — **קריאה מוצלחת אינה נוגעת בדגל כלל**, ולכן
מסלול ההצלחה נשאר זהה בית-בבית.

השומר מקבל תנאי שלישי:

| 4 | תמונה חדשה · `handleAnalyzerReset` · איפוס טופס | הדגל נקבע מחדש / מתאפס ל-`null` |

**מסלול קצה מתועד:** OCR נכשל על AFRM, המשתמש רוצה בכל זאת את המחיר החי
של AFRM ולא נוגע בשדה — עליו ללחוץ על צ'יפ המחיר (מסלול 3, קליק אחד,
הצ'יפ מציג את המחיר וגלוי). זו התנהגות מכוונת: אחרי OCR כושל, מחיר חי
בשדה הכניסה חייב להיות בחירה, לא ברירת מחדל.

**הקלדה ידנית ללא OCR:** הדגל `null` → אף תנאי לא נוסף → **התנהגות זהה
אחד-לאחד להיום.** זו דרישת-העל של הפרומפט, והיא נבדקת כתרחיש 3 בדפדפן.

**שני המסכים:** אותו טיפול ב-`fetchFormQuote`, עם `formOcrTickerRef`.
הדגל נקבע ב-**שני** מזיני הטופס — `handleImageUpload:2416` וגם
`routeChartOcr:2570` (מסלול הצ'ארט מזין את אותו `form`).

## 4. תצפיתיות — סגירת ממצא 10 באודיט

האודיט §4.2-4.3: אפס קריאות ב-24 השעות הנשמרות, אפס `console` בנקודה,
אפס סימן על העסקה. **הנתיב אינו מדיד בשום ממד.**

`src/lib/consent.js` הוא הבעלים היחיד של `window.gtag` בריפו. שם תיווסף:
```js
// Aggregate-only. Two enums, no identifiers: never a ticker, price or user id.
export function trackEvent(name, params) {
  if (readConsent() !== "granted") return;
  if (typeof window === "undefined" || typeof window.gtag !== "function") return;
  window.gtag("event", name, params);
}
```

נורה פעם אחת לכל תשובת OCR, בשלושת הצרכנים:
```js
trackEvent("ocr_result", {
  detected: ocrDetection(result),                    // full | partial | ticker_only | none
  confidence_bucket: conf >= 70 ? "high" : conf >= 40 ? "mid" : "low",
});
```

**גזירה מ-`ocrDetection` — אותה פונקציה שמזינה את הבאדג'.** מקור אמת אחד:
בלתי-אפשרי שהמדידה תספר "full" בזמן שהמשתמש רואה 🟠.

**⚠️ המכנה (§2) — חובה לרשום עכשיו, לפני שמישהו ידווח אחוז:**
האירוע נורה **רק כשה-consent הוא `granted`**. לכן הדוח היומי חייב לומר
*"N קריאות OCR בקרב משתמשים מסכימים"* ולעולם לא *"N קריאות OCR"*.
המכנה הוא אוכלוסיית-המסכימים, לא כלל המשתמשים. שורה ב-`docs/STATE.md`.

**⚠️ סטייה מהבקשה:** ביקשת `detected: full|ticker_only|none`. אני שולח
ארבעה ערכים, בהתאמה ל-`partial` של F3 — אחרת תרחיש D ייספר כ-`full`
והמדידה תשקר לטובתנו.
