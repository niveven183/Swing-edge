## שינויים

### 1. `src/utils.js` — מקור אמת אחד לפורמט כסף

מוסיפים ליבה משותפת אחת ובונים עליה את שני הפורמטרים:

```js
const money = (n, digits) => {
  if (!Number.isFinite(n)) return "—";
  const neg = n < 0 || Object.is(n, -0);
  return `${neg ? "-" : "+"}$${Math.abs(n).toLocaleString("en-US",
    { minimumFractionDigits: digits, maximumFractionDigits: digits })}`;
};
export const fmt$  = (n) => money(n, 2);   // FIN-028, FIN-029
export const fmt$0 = (n) => money(n, 0);   // חדש — דולרים שלמים, לתאי לוח שנה וצירים
```

- `fmt$0` הוא **קידום** של `money()` המקומי מ-`WeeklyReviewTab.jsx:22` לרמת `utils.js`
  (§13 "מקור-אמת-אחד"), עם הגנת `NaN`/`-0` שלא הייתה שם.
- `maximumFractionDigits: 2` הוא שינוי התנהגות זעיר ומכוון: היום `fmt$(1234.567)`
  מחזיר `+$1,234.567`. רוב הקוראים כבר מעגלים במעלה הזרם.

`fmtR` (`:129-132`) — להוסיף את אותה בדיקת `-0`:
```js
const neg = r < 0 || Object.is(r, -0);
```
`fmtR(0)` נשאר `"+0.00R"` — הערך הקפוא ב-`rContract-test.mjs:174` **אינו זז**
(`Object.is(0, -0) === false`).

`formatPct` / `formatReturnPct` (`:136,:140`) — FIN-030, אפס שקרי:
```js
const asNum = (v) => (v === "" || v == null ? NaN : Number(v));
export const formatPct       = (v) => Number.isFinite(asNum(v)) ? `${Math.round(asNum(v))}%` : "—";
export const formatReturnPct = (v) => Number.isFinite(asNum(v)) ? `${asNum(v).toFixed(2)}%` : "—";
```
**בדיקת רדיוס:** 19 קוראי `formatPct` ו-3 של `formatReturnPct` מקבלים מספר אמיתי
מ-`stats`. `EMPTY_STATS` (`src/lib/tradingStats.js:242`) מגדיר `winRate: 0` — מספר,
לא `null` — ולכן **מצב ריק ממשיך להציג `0%` ולא `—`**. רק ערך חסר באמת הופך ל-`—`.

### 3. `GrowthPredictor.jsx` — FIN-031

מפצלים את `pct` (`:274`) למספר ולמחרוזת, כדי שההשוואה תרוץ על המספר לפני העיגול:

```js
const pctNum = (val) => effectiveCapital > 0 ? ((val - effectiveCapital) / effectiveCapital) * 100 : 0;
const pct = (val) => { const r = Math.round(pctNum(val)); return `${r > 0 ? "+" : r < 0 ? "-" : ""}${Math.abs(r)}%`; };
```

`pct` מחזיר עכשיו מחרוזת **מלאה כולל הסימן והאחוז**, ולכן לוגיקת ה-`"+"` הכפולה
ב-`:584` וב-`:623` נמחקת — זה מה שהרכיב `"+" + "-0" + "%"`. הצבע (`:620`) נגזר
מ-`Math.round(pctNum(val))`: חיובי ירוק, שלילי אדום, **אפס ניטרלי** (slate) —
עקרון 1: אפס אינו איתות. איחוד הפורמטר מ-FIN-015 נשמר: מקור אחד לשני המשטחים.

### 4. `src/data/tooltips.js` — FIN-044, ראש התור

הנוסחה `R = (Exit − Entry) ÷ Initial Risk` נכונה ל-LONG בלבד. ב-SHORT מנצחת
היא נותנת R שלילי — **התיעוד מלמד את ההפך מהאמת**. `src/utils.js:44-46` כבר
מחשב נכון לפי `side`; רק הטקסט מפגר אחריו.

מתקנים **10 מחרוזות**: `avgR` ו-`rMultiple`, כל אחת ב-`en`/`he`/`es`/`pt`/`ar`.
הנוסח החדש (עברית לדוגמה):

> `R = רווח העסקה ÷ הסיכון הראשוני. ב-LONG הרווח הוא (יציאה − כניסה), ב-SHORT הוא
> (כניסה − יציאה) — כך ש-SHORT מנצחת היא תמיד R חיובי.`

המשפט על `null` R שנוסף ב-T3 (`עסקה בלי סטופ מוחרגת מהממוצע, ואינה נספרת כ-0R`)
**נשמר כלשונו** בכל חמש השפות.

📌 `docs/SwingEdge-Terms-Glossary.md` **נגזר** מ-`tooltips.js` דרך
`npm run glossary`. יורץ ויקומט **באותו קומיט**, אחרת התיעוד מתפצל מהמקור.

### 5. שער חדש — `scripts/format-test.mjs` → `test:format`

הבדיקות שהאודיט דורש מקבוצה 7 (`AUDIT…md:272-276`):

- **טבלת פורמט:** `fmt$`: `-0`→`-$0.00` · `0`→`+$0.00` · `NaN`/`±Infinity`/`null`→`—` ·

- **אפס שקרי:** `formatPct(null\|undefined\|NaN)` → `—`, `formatPct(0)` → `0%`.

- **grep-guard ממוקד:** `TradeCalendar.jsx` אינו מכיל `Math.abs(pnl)`;

הערה על היקף ה-grep: האודיט ביקש assertion גורף ש"אין פורמוט `$` inline מחוץ
ל-`utils.js`". **לא מיישמים אותו כלשונו** — הוא ייכשל היום על עשרות אתרים לגיטימיים
(`curEquity`, `capital`) שאינם P&L חתום, וכדי לעבור היינו צריכים להשתיק אותו,
מה שהופך אותו לשער ריק. במקומו — guard ממוקד על האתרים שתוקנו. הפער נרשם ב-STATE ⚠️.
