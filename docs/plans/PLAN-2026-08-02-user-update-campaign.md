## 1. שינוי ה-workflow — הדרך הפחות פולשנית

`email-campaign.yml` מקודד את הקהל בשני מקומות: שאילתת ה-fetch (L93-100)
ושאילתת "נותרו בתור" לדיסקורד (L248-251). שתיהן `public.waitlist`.

**נבחר: פרמטר `audience`** (`type: choice`), ברירת מחדל `waitlist_approved` —
התנהגות קיימת, byte-for-byte. ערך שני: `registered_users`.

**נדחה: שכפול ה-workflow** — שני קבצים שמתחזקים במקביל את אותו נתיב SMTP,
dedup ודיווח. תיקון באחד שלא יגיע לשני הוא כשל שקט מובנה.

**בטיחות SQL:** `audience` הוא `choice` — GitHub מגביל לערכים המוגדרים. בנוסף,
הערך בורר בין **שני heredocs קבועים** ב-`case`, ואינו משורשר לתוך SQL בשום
שלב. ברירת המחדל ב-`case` היא `exit 1`, לא נפילה לקהל כלשהו.

שאילתת הקהל החדש:

```sql
SET default_transaction_read_only = on;
SELECT u.email FROM auth.users u
WHERE u.deleted_at IS NULL
  AND u.banned_until IS NULL
  AND u.email_confirmed_at IS NOT NULL
  AND u.email ~ '^[^@[:space:]]+@[^@[:space:]]+\.[^@[:space:]]+$'
  AND u.email !~* '\.(local|localhost|test|invalid|example)$'
  AND NOT EXISTS (SELECT 1 FROM public.email_campaign_log l
    WHERE l.campaign = :'campaign'
      AND lower(l.email) = lower(u.email)
      AND l.status = 'sent')
ORDER BY u.created_at ASC
LIMIT :lim;
```

`deleted_at IS NULL` עונה על שאלת הציד: משתמש שנמחק **אינו** בקהל.
`banned_until IS NULL` ו-`email_confirmed_at IS NOT NULL` מוסיפים את אותה הגנה
לחשבון חסום ולכתובת לא מאומתת.
