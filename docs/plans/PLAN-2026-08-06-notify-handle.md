## 3. §1 — `GET /api/notify`

### האם זה שובר משהו קיים

**לא.** `GET` מחזיר היום 405 (`notify.js:181-184`) ואין לו צרכן — לא בקוד, לא
בתיעוד, לא ב-workflow. שום דבר לא נשען על ה-405.

### שלוש נקודות מימוש

1. `GET` נוסף ל-`Access-Control-Allow-Methods` (`:175`). `OPTIONS` ללא שינוי.
2. סדר הבדיקות ל-`GET`: config → `verifyUser` (401) → `is_admin` RPC (403) →
   רשימה. ⛔ **לא** בדיקת-method-ראשונה, אחרת `GET` בלי טוקן יחזיר 405 ולא 401.
3. ⚠️ **הכשל השקט שנמנע כאן.** ה-rate limiter הוא `3/10min` על `user.id`
   (`:200-204`). אם `GET` יחלוק את אותו מפתח, **פתיחת הפאנל שלוש פעמים שורפת
   את תקציב השליחה לעשר דקות** — הידית חוסמת את עצמה, בלי הודעה. `GET` מקבל
   מפתח נפרד (`notify_list`), וזה נאכף באסרציה 4.

### החוזה

```
GET /api/notify        Authorization: Bearer <jwt>
200 → { templates: [ { key, subject }, … ] }
401 → { error: "unauthorized" }     — אין טוקן / טוקן פסול
403 → { error: "forbidden" }        — טוקן תקין, לא אדמין
```

נגזר מ-`Object.entries(TEMPLATES)`. ⛔ בלי `file`, בלי נתיב, בלי HTML.
זהו מקור-האמת היחיד — ⛔ אפס hardcode של שם תבנית ב-JSX (אסרציה 6).

## 4. §3 — אבחון: התג אינו קורא מהמסד בכלל

### מה מרנדר את התג ומה הוא קורא

`REVIEWED_FEEDBACK_KEY = "swingEdgeReviewedFeedback"` (`AdminPanel.jsx:18`) הוא
מפתח **localStorage**.

- `markReviewed` (`:1120-1124`) כותב ל-localStorage בלבד. **לעולם לא נוגע במסד.**
- `getStatus` (`:1107-1111`): `f.status === "resolved"` → `resolved`; אחרת
  localStorage → `reviewed`; אחרת `new`.
- הבאדג' ב-`:1201` מצייר את מה ש-`getStatus` החזיר.

### שלוש תוצאות

1. **הצילום מ-05.08 הוא הדפדפן של ניב.** במכשיר אחר, בדפדפן אחר, או אחרי ניקוי
   אחסון — אותם חמישה מוצגים `new`. שום דבר לא נרשם מעולם.
2. **`getStatus` לעולם אינו קורא `f.status === "reviewed"`.** אילו שורה *כן*
   הייתה `reviewed` במסד, הפאנל היה מצייר אותה `new`. שני המצבים חולקים תווית
   ותו לא — הם זרים זה לזה.
3. `unreadFeedbackCount` (`:362-367`) קורא מאותו localStorage → **תג הניווט
   משקר באותה דרך בדיוק**, וזה התג שקובע אם ניב בכלל פותח את הטאב.

### למה במסד יש רק שני ערכים — הוכחה סטטית, חזקה מספירה

אין מסלול קוד שיכול לכתוב `reviewed`: `markResolved` (`:1128`) שולח
`resolved`/`new` בלבד, ו-`markReviewed` אינו פונה למסד. הספירה
`new (5) / resolved (3)` אינה מקרית ואינה נקודתית — היא **הכרחית**.

### ⚠️ סטייה מהנחת הפרומפט

§3 אומר: "אם ההגדרה במסד דו-מצבית, ה-UI חייב לשקף שניים בלבד."
**ההגדרה אינה דו-מצבית:**

- `admin_set_feedback_status` מתיר שלושה — `20260719120000_admin_rpcs.sql:379`.
- מיגרציית S1 **סירבה במפורש** להוסיף CHECK כדי לשמור על השלישי חוקי —
  `20260802120000_s1_rls_hardening.sql:126-128`, בלשונה: *"במכוון **אין** CHECK
  על feedback.status … אילוץ כאן היה חוסם ערך חוקי שהפאנל שולח אך טרם נכתב."*

כלומר הסכימה תלת-מצבית **בכוונה מתועדת**; רק הנתונים דו-מצביים, והסיבה היא
שהכותב למצב השלישי מעולם לא נבנה. התנאי שבפרומפט אינו מתקיים, ולכן "לשקף
שניים" היה מוחק מצב שהמסד שימר במכוון ומטפל בסימפטום.

### 🔴 שתי חלופות — החלטת ניב

| | מה | עלות |
|---|---|---|
| **A — מומלץ** | `markReviewed` → `admin_set_feedback_status(_id,'reviewed')`. `getStatus` מחזיר `f.status` בלבד. `REVIEWED_FEEDBACK_KEY` ושני קוראיו נמחקים | אפס מיגרציות; RPC קיים ומגודר. המצב נעשה אמיתי, חוצה-מכשיר, ונותן ל-`CLAUDE.md` §10.2 ("Reviewed הוא מצב ביניים, לא סיום") מקום לחיות בו |
| **B** | להסיר את `reviewed` מה-UI לחלוטין — שני מצבים | מוחק מצב שמיגרציית S1 שימרה במכוון; §10.2 נשאר בלי ייצוג |

⚠️ ב-A ה-localStorage הקיים של ניב **אינו** מהגר — חמש השורות יחזרו להיות

## 5. §2 — הידית בפאנל

### `src/lib/replyGate.js` — למה מודול נפרד

מודול **טהור, אפס imports**: `nextState(state, event)` · `canSend(state)`.
קיים כדי שהאינווריאנט "שלח חסום לפני יבש תקין" יהיה בר-אסרציה **בשרשרת
החוסמת** — `AdminPanel.jsx` אינו ניתן לייבוא ב-node (גורר recharts, lucide,
supabaseClient), ו-`test:smoke` אינו בשרשרת ואינו חוסם push. בלי המודול הזה
האינווריאנט היה נשען על עין אנושית, כלומר לא היה נאכף.

### שלושת השלבים

| שלב | מה | חסימה |
|---|---|---|
| **א** | `<select>` תבנית, מאוכלס מ-`GET` | "בדוק" חסום בלי בחירה |
| **ב** | `POST` `dry_run:true` → מציג **נושא** · **כתובת ממוסכת** · **האם כבר נשלח** | — |
| **ג** | כפתור **"שלח"** נפרד | ⛔ `disabled` עד `canSend(state)` |

- ⚠️ **החלפת תבנית מאפסת לשלב א.** אחרת מריצים יבש על X ושולחים Y — חור אמיתי,
  לא תיאורטי.
- שלב ב הוא נקודת האימות האנושית ש-`notify.js:113-117` תוכנן סביבה
  (`feedback.user_email` נותר caller-asserted בשורות קיימות). ⛔ לא למזג לשלב ג.
- ⛔ **אין סימון `resolved` אוטומטי.** `resolved` = הבקשה יושמה, לא שנשלחה תשובה.
- שגיאת שרת מוצגת **כלשונה** מ-`json.error`. ⛔ אפס catch שותק.
- תצוגת "נשלח + מתי" ליד השורה מקורה **`email_campaign_log`**, לא state מקומי —
