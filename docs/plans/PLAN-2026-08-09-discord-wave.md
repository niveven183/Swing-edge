## §1 — ה-Digest מכיר את הליגר

### 1.1 מבנה ה-JOIN — **נמדד, לא שוער**

```sql
SELECT campaign, status, length(campaign) FROM email_campaign_log
WHERE campaign LIKE 'reply:%' ORDER BY sent_at;
```

```
reply:eebd6bb1-ff20-4894-9d07-b12026167f2d | sent | 42   ← 07.08 12:06
reply:f95b837e-94c7-49cb-893b-4f8242b6f6e9 | sent | 42   ← 07.08 19:09
```

**שתי השורות היחידות בליגר הן הצורה הישנה:** `reply:<uuid>` — `6 + 36 = 42`
תווים, **ללא** סיומת `:n:h8`. ה-id הוא **UUID מלא**, לא 8 תווים.

**המסקנה שקובעת את התכנון:** `campaign = 'reply:' || id` נכון **היום** ונשבר
ברגע שיישלח המענה הבא — שייכתב בצורה `reply:<id>:<n>:<h8>` (`replyLedger.js:59`).
`LIKE 'reply:<id>%'` מכסה את שתי הצורות (UUID אינו מכיל `%` או `_`, ולכן
אין מטא-תו).

### 1.2 ⛔ אבל ה-JOIN לא ייעשה ב-SQL

`api/_lib/replyLedger.js:5-7` קובע:

> *"A second copy of the parse is the exact drift the GET template list was built
> to remove, and it fails silently."*

פרסר ב-SQL יהיה **הפרסר השלישי**. הסיווג ייעשה ב-JS דרך
**`parseCampaign` המיובא מ-`api/_lib/replyLedger.js`** — מקור-אמת-אחד
(`CLAUDE.md` §13), ושתי הצורות מתקפלות לאותו `{ id, n, hash }` כבר היום
(`replyLedger.js:40-42`). ✅ `package.json` הוא `"type": "module"`, וה-import
מ-`scripts/` ל-`api/_lib/` נתמך.
