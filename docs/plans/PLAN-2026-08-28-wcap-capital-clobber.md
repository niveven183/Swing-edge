## 1 · P1 + P2 — עצירת הכתיבה (הסדר שניב קבע)

⚠️ **הערה על הסדר.** הכתיבה **כבר** חסומה ב-`hydratedRef` (`SwingEdge_App.jsx:1792`).
היא עוברת רק מפני שקריאה **כושלת** מסמנת את השער `true`.
⇒ ⛔ **אין «עצירת כתיבה» שאינה גם תיקון הקריאה** — פרט למסלול אחד, וזה מה שנעשה ראשון.

### שלב 1a — `src/lib/userSettings.js:151-163` · מסלול הדריסה הנקי, שורה אחת

היום בדיקת-הקיום ב-`migrateFromLocalStorage` שחוזרת עם `{ error }` **נופלת דרך**
(`if (!error && data)` = false) ⇒ הפונקציה ממשיכה, בונה blob מ-localStorage, ו-`upsertBlob`
**דורס שורה קיימת**. ה-`catch` ב-`:161` תופס **זריקות בלבד** — ו-supabase-js ⛔ אינו זורק.

```js
if (error) return { migrated: false, reason: "check-failed" };
if (data)  return { migrated: false, reason: "exists" };
```

⇒ **מסלול דריסה שלם נעלם, ⛔ בלי לגעת בהידרציה.** זו «עצירת הכתיבה» במובן המילולי.

### שלב 1b — `src/lib/userSettings.js:101-121` · תוצאה מובחנת (סוגר `B-269`)

```js
// { status: "ok" | "empty" | "failed", settings }
//   ok     — נקראה שורה עם settings
//   empty  — maybeSingle החזירה {data:null, error:null} ⇒ סמכותי, אין שורה. כתיבה מותרת.
//   failed — error לא-ריק · זריקה · ⛔ אין client/userId.  ⇒ כתיבה חסומה.
```

- ב-`failed`: `console.error("userSettings: load rejected", error.message || error)` —
  **בדיוק הצורה** ש-`upsertBlob:90` כבר משתמש בה (`INCIDENTS#15`).
- ב-`failed`: המראה נקראת ל**תצוגה** אבל ⛔ **בלי `cache.set`**. היום `:119` מרעיל את
  ה-cache ב-`{}`, ו-`flushSettings:145` מעלה את ה-`{}` הזה ל-DB.
- ⛔ **החוזה אינו משתנה:** קריאה/כתיבת הגדרות ⛔ לעולם אינה זורקת.

⚠️ **בוליאני דו-ערכי היה שגוי.** משתמש חדש (⛔ אין שורה) **חייב** להצליח לכתוב שורה ראשונה.
ההבחנה `empty` ≠ `failed` היא בדיוק מה שמונע רגרסיה למשתמש חדש — ולכן שלושה מצבים, לא שניים.

**קונסומרים:** אתר-קריאה **יחיד** באפליקציה (`SwingEdge_App.jsx:1722`) + `scripts/userSettings-test.mjs`.
⇒ משנים חתימה **במקום**, ⛔ בלי wrapper ו⛔ בלי עותק שני (§13 מקור-אמת-אחד · `R-6`).
