## 0. ההנחה המרכזית בפרומפט — הופרכה במדידה

הפרומפט מורה: «לכל אחת שהיא שער — החלף ל-`toHaveCount(n, {timeout})`».

הרצתי probe אמפירי ב-Chromium אמיתי (Playwright 1.61.1 / Chromium 1243) מול דף
שבו `[data-boundary="risk"]` מופיע אחרי `1500ms`:

```
A  bare count()          -> 0        (19ms)
B  toHaveCount(0,{5000}) -> PASSED   (12ms)   ← עבר בלי לזרוק
C  toHaveCount(1,{5000}) -> PASSED   (1801ms) ← חיכה באמת
D  settle-then-count     -> 0        (17ms)   ← העוגן שנבחר היה שגוי
```

`toHaveCount` מתשאל עד שהתנאי הופך **אמיתי**:

- **ציפייה-לנוכחות** (`toHaveCount(1)`) — חוזר ומנסה באמת (צורה `C`, `1801ms`).
- **ציפייה-להיעדר** (`toHaveCount(0)`) — עובר ב**תשאול הראשון**, כי `count === 0`
  כבר אמיתי ⇒ **אפס הגנה מפני אפס-מוקדם** (צורה `B`, `12ms`, על דף שעמד לרנדר
  כרטיס קריסה).

⛔ **ההחלפה המוצעת מועילה ל-5 שערים ו⛔ מועילה ל-4 אחרים — וביניהם `:392`
ו-`:416`, שהם כל ההוכחה של `B-304`.**

### בלוק 1 — 5 שערי נוכחות (`:436` `:442` `:459` `:683` `:687`)

משלו ⇒ ה-`got` ייגזר מ-`e.message`, ⛔ ייכתב ביד.
