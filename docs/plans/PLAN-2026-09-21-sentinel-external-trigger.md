⚠️ **וזה פוסל אותו גם אילו התדר היה מספיק** — ולכן **⛔ מדדתי את מדרגת החשבון**:

Vercel Cron ⛔ בשימוש היום בכל מקרה.

**קריטריונים נוספים:** ⓵ ⛔ GitHub Actions בריפו אחר — **אותו מתזמן, אותה
נשירה**, זו הנחה שכבר הופרכה. ⓶ הספק מחזיק PAT ⇒ אמון. ⓷ כמה עבודה ידנית קבועה

(`:22-26`). ⇒ **החשש ש-`B-318` יחסום את הטריגר החיצוני — הופרך.**

⚠️ **אבל `run_auth` ברירת-מחדל `true`** ⇒ טריגר חיצוני שלא מציין דבר מריץ auth
**`48`/יום**. ⇒ **חובה לציין `run_auth` מפורשות בכל קריאה**: `"false"` ב-`:05`,
`"true"` ב-`:35` — כך auth נשאר `24`/יום כמתוכנן, ⛔ `48`.
⚠️ **ו-`${RUN_AUTH:-true}` פירושו שקלט *ריק* נופל ל-`auth=1`** — ברירת המחדל
בטוחה בכיוון «ירוץ», ⛔ בכיוון «יידלג». זה נכון כאן, **ומחייב אימות** שה-REST

**ⓑ 🔴 כל `workflow_dispatch` מדליק את השכבות ה«יומיות» — וזה חוסם.**
`sentinel.yml:171` הוא `[ "${GH_EVENT:-}" = "workflow_dispatch" ] && daily=1` ⇒
**כל** קריאה חיצונית מריצה את Layer C (RDAP) ו-Layer D (כותרות אבטחה + תוכן
מעורב). ⇒ `48`/יום במקום `9/62` ימים שנמדדו (`B-356`). **`48` שאילתות RDAP ביום
מול רשם הדומיין** הן חשיפה לחסימת-קצב, והשינוי מגיע **בחשאי** כתופעת לוואי של א׳.

🟢 **התיקון — קלט `daily` באותה צורה של `run_auth`:**
```yaml

        description: 'Run the once-a-day layers (C: RDAP, D: security headers)'
        type: boolean
        default: true        # ⛔ false — משמר את התנהגות ההרצה הידנית של ניב
```

ב-`47/48` הקריאות ו-`"true"` באחת. ⚠️ **ברירת המחדל `true` ⛔ שרירותית** — היא
משמרת **בדיוק** את מה שהרצה ידנית עושה היום; ברירת מחדל `false` הייתה משנה בשקט
את כלי הדיבוג של ניב, וזה שינוי התנהגות שלא ביקשנו.
⚠️ **וזה ⛔ סוגר את `B-356`** — הענף `date -u +%H` נשאר חי עבור הערוץ המתוזמן;
